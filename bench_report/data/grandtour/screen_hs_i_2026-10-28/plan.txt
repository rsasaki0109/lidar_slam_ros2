Ninth screen on the HS rig: level the frame while the robot stands after a moving start (2026-10-28, written before
any of these runs).

Why: the eighth screen's standstill handling helps SNOW-3 (hold) and the static starts (bias), but loses ICE-1 and
ARC-6, both moving starts: the standstill bias update takes the moving start's frame tilt for an accelerometer bias.
rko_lio d0e9027 adds start_standstill_level_sec: after a moving start, the standing intervals near the start collect
their mean specific force (no bias update), and once they add up to that long the state is rotated about the sensor's
position so the world z is up, the maps start again there, and the output filter starts (the moving start had held it
off). Static starts are unchanged by it. Tests 110/110 (a walking start tilted 11.5 deg is levelled to < 0.1 deg).
Variants (ws/rko_g22; HS-G15c + start_standstill_radius 1.0 + start_standstill_level_sec 1.0, not tuned):
  lv  = the above (no hold);
  lvh = the above + start_standstill_hold (the eighth screen's ss with the levelling).
Missions: lv and lvh on the moving starts snow-3, arc-5, arc-4, ice-1, arc-6; lv on the static starts arc-3, arc-1,
pil-2, heap-1 (there lvh is the eighth screen's ss: the levelling acts only after a moving start). Compared with
HS-G15c and the eighth screen. Reported: ATE without reference spikes, jitter, the tilt levelled (log). A screen: a
candidate it picks is judged on all 15 HS missions under a rule fixed before those runs.
