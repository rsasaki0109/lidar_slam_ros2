What is submitted
  The frontend (RKO-LIO) alone with the GrandTour configuration HS-G15c, unchanged:
    configs/sota_v7/rko_lio_grandtour_hs_G15c_2026-10-27.yaml   md5 40024bc65fc6c3931b68f3228ddc81a3
    rko_lio 9461e71 (branch claude/jolly-gauss-dliz8l), ws/rko_g21 offline_node md5 ef174ce6905e4fc5d090a4e12dae9799
  HS-G15c = HS-G15b (HS-G15 + point-to-point terms only after 3 m from the start) + the causal output position filter
  (decision_rule_G15b.txt, decision_rule_G15c.txt). It is NOT the project's global configuration G: it was chosen on
  GrandTour development missions, for the HS rig only. The submission is labelled as GrandTour-specific.
  The output filter is causal and runs online: each output position comes from the IMU samples and registered scans up
  to its own time (an IMU-driven filter with the registered positions as measurements); no pose is changed afterwards.
  After a moving start (the log's "Moving start") the filter stays off and the output is the registration's.
  Rig inputs (HS): the Hesai XT-32 point cloud and the STIM320 IMU; the STIM320 frame is the base frame; extrinsics
  from the export's `transform` attributes; T_world_prism(t) = T_world_stim320(t) T_stim320_prism with box_base ->
  prism from tf_static, as in submissions 1 to 3.
  Category: LiDAR + IMU (no camera, GNSS or external odometry). Real-time: yes (node time below the mission span on
  every GrandTour development mission).

Policy
  0. Before the test runs, the configuration file is run on one development mission (spx-3, a static start, so the
     filter is on) and must give the same trajectory, byte for byte, as the G15c confirmation run (G15c_g15c/spx-3,
     front_tum md5 26e7144ca4ab421f3adf43b8ef50296a); otherwise nothing is run.
  1. The six test trajectories are produced in one batch (p1_grandtour_batch.sh, LIDAR=hesai_points IMU=stim320_imu,
     G_CONFIG the file above, WS=ws/rko_g21) and packed into one zip; the md5 of every file is recorded here before
     the zip leaves the VM.
  2. If the maintainer uploads it, it is uploaded once as the next test-phase submission, and the scores are recorded
     whatever they are.
  3. A pipeline failure is fixed and recorded; a poor trajectory because of HS-G15c or the rig is submitted as is.

Fact sheet (proposed)
  Method name: lidar_slam_ros2 (RKO-LIO frontend, GrandTour configuration HS-G15c). Description: LiDAR-inertial odometry
  with bump-image (voxel-wise height image) and point-to-point registration and a causal IMU-driven output position
  filter, Hesai XT-32 + STIM320, frontend output only, no loop closure, no post-processing; configuration selected on
  GrandTour training missions. Novel: yes. Real-time: yes. LiDAR: yes. IMU: yes. Camera: no. GNSS: no. External
  odometry: no.
