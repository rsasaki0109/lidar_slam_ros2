Policy
  0. Before the test runs, the configuration file is run on one development mission (arc-4) and must give the same
     trajectory, byte for byte, as the G15 confirmation run (G15hs_g15/arc-4); otherwise nothing is run.
  1. The six test trajectories are produced in one batch (p1_grandtour_batch.sh, LIDAR=hesai_points IMU=stim320_imu,
     G_CONFIG the file above, WS=ws/rko_g15) and packed into one zip; the md5 of every file is recorded here before the
     zip leaves the VM.
  2. If the maintainer uploads it, it is uploaded once as the next test-phase submission, and the scores are recorded
     whatever they are.
  3. A pipeline failure is fixed and recorded; a poor trajectory because of HS-G15 or the rig is submitted as is.

Fact sheet (proposed)
  Method name: lidar_slam_ros2 (RKO-LIO frontend, GrandTour configuration HS-G15). Description: LiDAR-inertial odometry
  with bump-image (voxel-wise height image) and point-to-point registration, Hesai XT-32 + STIM320, frontend output
  only, no loop closure, no post-processing; configuration selected on GrandTour training missions. Novel: yes.
  Real-time: yes. LiDAR: yes. IMU: yes. Camera: no. GNSS: no. External odometry: no.
