# lidarslam_ros2 v0.11.0

> **Release candidate status — HOLD; not published or tagged**

v0.11.0 is the next release candidate of the supported Humble and Jazzy
rosbag2-to-Autoware-compatible map workflow. [v0.10.0](v0.10.0.md) is the
latest published release; use its pinned `v0.10.0-humble` and
`v0.10.0-jazzy` images and its notes for the supported routes. The
[v0.10.1](v0.10.1.md) candidate was never tagged; its changes ship in
v0.11.0.

This file becomes the public GitHub Release body verbatim. The tag workflow
therefore refuses this candidate-only banner and the HOLD decision below. A
maintainer must first satisfy the release gates, replace them with the final
verification section, and commit that review before creating `v0.11.0`.

## Shortest supported paths

These are unchanged from v0.10.0:

- `lidarslam-map doctor`, then `lidarslam-map demo <new-output-dir>` for the
  fixed public MID-360 demo;
- `lidarslam-map doctor /path/to/rosbag2`, then
  `lidarslam-map start /path/to/rosbag2` for your own bag.

## Changes since v0.10.0

- **Several runs of one site, one map.** `graph_slam_multisession_join` joins
  separate runs into one pose graph with no position hint. It refuses
  ambiguous sets and self-similar places rather than guess. It needs
  small_gicp. See
  [Multi-session join](../architecture/multisession-join.md).
- **Loop closure no longer drops input.** The loop search runs on a worker
  thread, so the backend builds every submap and repeats its output from run
  to run.
- **The backend places RKO-LIO's scan with its LiDAR-to-base extrinsic.** With
  a non-identity extrinsic (HILTI, for example), maps and trajectories change.
- **Default runs repeat.** The offline node waits for graph_based_slam before
  it publishes.
- **Less memory and a faster backend, same outputs.** Stored scans are packed
  and compressed, large maps are saved without assembling them, and the final
  map refinement is 2.4 times faster. Outputs are byte-identical.
- **`--motion walking`** for the MID-360 preset, with the frontend and loop
  settings adopted on humanoid walking data.
- **Large maps are downsampled again.** A map whose extent overflowed PCL
  VoxelGrid's voxel index used to be saved with every point.
- **Official RKO-LIO 0.4.1 and later** (ROS apt ships 0.4.2) save a map again.
- **`lidarslam-map`** works on the session directories `start` creates
  (`edit`, `view`, `inspect`), survives a slow first start, and checks free
  space before writing.
- Optional backend features: `SMALL_GICP` loop registration, a loop drift
  gate, fixed loop-edge information, and a causal trajectory output in
  `graph_slam_offline_runner`. All are off by default.
- The first independent first-map validation is accepted (1 of the 3 that
  v1.0 needs).

With loop closure on, or with a non-identity LiDAR extrinsic, results differ
from v0.10.0. The full list is in
[CHANGELOG.md](https://github.com/rsasaki0109/lidar_slam_ros2/blob/develop/CHANGELOG.md).

## Release decision: HOLD

No release gate has run for this candidate yet. Before tagging, run on the
exact final commit:

- `bash scripts/run_product_python_tests.sh` and strict MkDocs;
- the fixed demo, `lidarslam-map doctor`, and bundle reproducibility;
- `bash scripts/run_release_readiness_checks.sh --fail-on-profiles` with
  exact-commit evidence for `newer_college_math_hard`, `ntu_viral_tnp_01`,
  `mid360_gt_rtkslam_construction_seq2`, `mid360_gt_rtkslam_construction_seq1`,
  and `leo_drive_applanix_velodyne_cross`. A fresh NTU VIRAL preparation starts
  with `bash scripts/download_ntu_viral_tnp01.sh --dry-run`.

Only results from that exact commit may replace this HOLD section and the
candidate banner.
