# lidarslam_ros2 v0.13.0

> **Release candidate status — HOLD; not published or tagged**

v0.13.0 is the next release candidate of the supported Humble and Jazzy
rosbag2-to-Autoware-compatible map workflow. [v0.12.0](v0.12.0.md) is the
latest published release; use its notes for the supported routes.

This file becomes the public GitHub Release body verbatim. The tag workflow
therefore refuses this candidate-only banner and the HOLD decision below. A
maintainer must first satisfy the release gates, replace them with the final
verification section, and commit that review before creating `v0.13.0`.

## Shortest supported paths

These are unchanged from v0.12.0:

- `lidarslam-map doctor`, then `lidarslam-map demo <new-output-dir>` for the
  fixed public MID-360 demo;
- `lidarslam-map doctor /path/to/rosbag2`, then
  `lidarslam-map start /path/to/rosbag2` for your own bag;
- `pip install lidarslam`, then
  `lidarslam-map start /path/to/rosbag2 --engine core` without ROS 2
  (preview).

## Changes since v0.12.0

- **GNSS anchors without ROS 2.** With `use_gnss` (for example
  `--lidarslam-param lidarslam_rtk_gnss.yaml`), `graph_slam_offline_runner`
  and the `lidarslam` package anchor the map to the bag's RTK GNSS as the live
  node does. With `use_gnss` false every output is byte-identical.
- **Velodyne packets without ROS 2.** The `lidarslam` package decodes
  `velodyne_msgs/msg/VelodyneScan` with velodyne_pointcloud's decoder
  (vendored, BSD-3-Clause), byte-identical to velodyne_transform_node's cloud.
  `lidarslam-map run|start --engine core` maps a VelodyneScan + Imu bag with
  the RKO-LIO profile; the classic NDT packet profile still needs ROS 2.

The full list is in
[CHANGELOG.md](https://github.com/rsasaki0109/lidar_slam_ros2/blob/develop/CHANGELOG.md).
