# lidarslam_ros2 v0.9.1

> **Release candidate status — HOLD; not published or tagged**

v0.9.1 is a reliability and first-map usability release candidate for the
supported Humble and Jazzy rosbag2-to-Autoware-compatible-map workflow. It
does not claim v1.0 readiness, universal sensor support, or overall
superiority to GLIM.

This file becomes the public GitHub Release body verbatim. The tag workflow
therefore refuses this candidate-only banner and the HOLD decision below. A
maintainer must first satisfy the release gates, update this document to the
verified final `Release verification` state, and commit that review before
creating `v0.9.1`.

## Shortest supported paths

Start at [Autoware-Compatible Map Authoring](../autoware-map-authoring.md); it
keeps the public workflow in task order and separates stable from candidate
delivery.

- For the currently published fixed demo, use the pinned `v0.9.0-humble` or
  `v0.9.0-jazzy` image from [Getting Started](../getting-started.md).
- To evaluate this exact source candidate, use the six-package source
  quickstart, then run `lidarslam-map doctor` and `lidarslam-map demo`.
- For an installed own-bag path, run
  `lidarslam-map doctor /path/to/rosbag2`, then
  `lidarslam-map start /path/to/rosbag2`.
- Run `lidarslam-map` with no arguments in an interactive terminal when the
  first intent is not yet clear. It offers only installation check, demo, own
  bag, and retained sessions.
- Use the Japanese beginner page for the same commands and safety boundaries;
  it is not a separate execution fork.

Published v0.9.0 images predate the candidate own-bag `start` contract and are
rejected by its host launcher. Do not present that no-install path as stable
until a version-matched v0.9.1 image has been published and audited.
GLIM-style PPA/package-manager installation is also still unavailable. Source
and the published fixed-demo images remain the honest current routes until the
NDT ownership, rosdistro, and package-manager gates complete.

## Reliability and recovery

- All classic scanmatcher PCL VoxelGrid call sites reject unsafe dimensions,
  absolute-index overflow, invalid leaf sizes, and inconsistent dense clouds
  before entering PCL. The process and last valid map remain available, and a
  later safe frame can map normally.
- Mapping outputs retain atomic finalization, repaired ROS-log links, terminal
  manifests, diagnosis, verification logs, privacy-bounded first-map receipts,
  and a finalization-only `demo --resume` path.
- Existing, overlapping, symlinked, incomplete, or unverified output is
  refused with stable reason codes and one concrete next action.
- The canonical NTU benchmark acquisition now starts with the write- and
  network-free `bash scripts/download_ntu_viral_tnp01.sh --dry-run`. It reports
  every remaining multi-gigabyte phase, pins the
  official archive byte count and checksum, checks conservative destination
  capacity, and stops before download when the selected filesystem is too
  small.

## First-map and map lifecycle

- Docker and source demos share the fixed public MID-360 input, profile,
  verifier, manifest, diagnosis, and first-map receipt contract.
- The own-bag path performs sensor/profile review before writes and supports
  PointCloud2+Imu, PointCloud2+NavSatFix, and VelodyneScan+Applanix inputs.
- Users adapting another PointCloud2 LiDAR are routed through the same
  `doctor` then `start` path instead of editing tracked launch/YAML files.
  Topics, frames, fields, timestamps, maintained-profile selection, and
  calibration review remain explicit; detection alone is not a hardware or
  accuracy claim.
- The Docker own-bag launcher supports a schema-backed `--dry-run --json` plan
  for CI and wrappers; it performs no Docker, network, or filesystem writes and
  keeps local paths out of issue-reporting guidance.
- Completed sessions can be reopened, compared, inspected in the offline 3D
  viewer, edited through source-preserving plans, merged across visits, and
  converted into privacy-first support or independent first-map reports.
- `lidarslam-map inspect --symptom` turns five recurring visual map problems
  into ordered review checks and copy-ready product commands. It records a
  user report without changing parameters, rerunning mapping, or claiming an
  automatic root cause or accuracy result.
- `lidarslam-map support` preserves that report through the maintainer handoff
  as a fixed symptom code plus the user-reported evidence boundary. It excludes
  symptom titles, checks, commands, and free text from the ZIP.

## Distribution preparation

- Source onboarding detects Humble/Jazzy, verifies exactly six maintained
  packages, installs repository-only dependencies, builds that fixed list, and
  prints an absolute launcher that works from a fresh terminal.
- Runtime-image generation removes source and builder content while preserving
  installed CLI behavior and exact image-size evidence.
- The release pipeline builds a standalone `lidarslam-map-docker` launcher
  whose version, source revision, image identity, read-only bag mount,
  no-network execution, and output boundary are release-audited.
- Release bundle rehearsal is bound to the exact candidate head, fetches
  immutable tags, and refuses release-version reuse before publication.

These capabilities do not by themselves authorize a tag, package, image,
fixture, launcher, or release publication.
